# Trigger spec issues (qwen3:8b, 2026-09-27)

Baseline for comparing spec quality between models (section 6). Specs in `cache/triggers/`, generated by
qwen3:8b from the advisory text plus the fix diff. **Nothing here was fixed or overridden**; the evaluation runs used
these specs as they are.

How each issue affects a verdict:
- **miss risk**: can produce a wrong *not affected* (the dangerous direction)
- **false alarm**: can produce a wrong *affected*
- **coverage**: leads to *needs review* where a firm answer was possible
- **harmless**: wrong, but does not change a verdict with today's matching

## Summary

Counts are approximate (a spec can have several issues).

| category | specs |
|---|---|
| Missing `parent_triggers` for a package used mostly through another (urllib3 / certifi via requests) | 9 |
| Trigger is an internal / defining-module name instead of the public API | 12 |
| Trigger too broad (a common API that is not the vulnerable path) | 7 |
| Wrong API (the listed API is not where the flaw is) | 7 |
| Distribution name instead of import name (`Pillow.` instead of `PIL.`) | 4 |
| `arg_forms` that are descriptions, not argument values (cannot match anything) | 14 |
| Wrong `when_absent` / wrong `input_arg` | 2 |
| Typos / malformed symbols | 3 |
| Nonsense `parent_triggers` | 3 |
| Bundled-native wrapper list is the whole package or an internal module | 4 |
| Empty spec (no trigger at all) | 5 |

Only 13 of the 53 specs looked correct and complete enough to decide in code (e.g. CVE-2025-50181 correctly says requests
does not reach it, CVE-2024-5569 zipp, CVE-2026-45409 idna, CVE-2023-50447 ImageMath.eval).

## Per spec

### pyyaml
- **CVE-2020-14343**: `trigger_symbols` = `yaml.full_load`, `yaml.FullLoader` only. Missing `yaml.load`,
  `yaml.load_all`, `yaml.full_load_all`, `yaml.unsafe_load`, `yaml.UnsafeLoader`. The `Loader` arg_form is attached to
  `yaml.full_load` (which has no Loader argument) instead of `yaml.load`. `input_arg` = "1" (the document is argument 0).
  *miss risk*: `yaml.load(body)` (no Loader: dangerous in 5.3.1) would only be caught if `FullLoader` also appears.
  In safe-args the right answer came from "present: not used" instead of "Loader=SafeLoader is safe".

### rsa
- **CVE-2020-25658**: `rsa.pkcs1.decrypt` (defining module) instead of the public `rsa.decrypt`; arg_form
  `crypto: ['bytes']` is a type, not a value. *miss risk* (fixed by public-name matching).

### pygments
- **CVE-2022-40896**: SmithyLexer only; no lookup functions (`get_lexer_by_name`, `guess_lexer`, `get_lexer_for_filename`).
  arg_form `lexer: ['SmithyLexer']` is not an argument of the class. *miss risk* for apps that pick lexers by name.
- **CVE-2026-4539**: AdlLexer only; same missing lookup functions. *miss risk*: in the indirection repo only the code-level
  "lookup by runtime name" rule kept this from being ruled out.

### requests
- **CVE-2023-32681**: trigger is the internal `requests.sessions.Session.rebuild_proxies`; the public APIs are any request
  call made through a proxy with credentials (proxies can also come from environment variables). *miss risk*.
- **CVE-2024-35195**: arg_forms only for `Session.get` / `Session.post` (not `request`, `put`, …); `when_absent` =
  "dangerous" although `verify` defaults to True. *false alarm* for sessions that never pass `verify`.
- **CVE-2024-47081**: `dangerous_condition` = "trust_env is True" and an arg_form on a `trust_env` keyword that request
  methods do not have (it is a Session attribute). Trigger list misses `Session.get` etc. (covered by the class-sibling
  rule). *coverage*.
- **CVE-2026-25645**: correct (`requests.utils.extract_zipped_paths`); typo `extract_zipped,paths` in the condition. *harmless*.

### urllib3 (used only through requests in the test repos)
- **CVE-2023-43804, CVE-2023-45803, CVE-2024-37891, CVE-2025-66418, CVE-2025-66471, CVE-2026-21441, CVE-2026-44431**:
  no `parent_triggers` entry for requests. For 66418 / 66471 requests **does** reach the code (it decodes response bodies
  through urllib3); for the redirect-related ones it does **not** (requests passes `redirect=False` and follows redirects
  itself). *coverage* (all 7 end as needs review; 2 of them are expected affected).
- **CVE-2025-66418**: trigger is the internal `urllib3.response.MultiDecoder`. *coverage*.
- **CVE-2026-21441**: trigger is the internal `HTTPResponse.drain_conn`. *harmless* here.
- **CVE-2026-44431**: malformed trigger `urllib3.ProxyManager.connection_from, `. *coverage*.
- **CVE-2025-50181**: correct, including `requests` reachable=false. Good example.

### certifi
- **CVE-2023-37920, CVE-2024-39689**: empty trigger list and no `parent_triggers`, although certifi's bundle is used by
  requests for every HTTPS request with default verification. *coverage* (both expected affected, both needs review).

### jinja2
- **CVE-2025-27516** (sandbox escape via `|attr`): triggers `jinja2.Template`, `jinja2.Environment`; missing
  `jinja2.sandbox.SandboxedEnvironment`, the only class the flaw matters for, and the condition does not mention the
  sandbox. *miss risk* (caught only by the likely-subclass rule, as needs review).
- **CVE-2024-56201**: only `jinja2.Template`; misses `Environment.from_string` / `get_template`. *miss risk*.
- **CVE-2024-56326**: typo `jinja,Template`; arg_form (`loader: SandboxedPolicy`) is invented. `parent_triggers`
  Flask → `render_template_string` is reasonable. *coverage*.
- **CVE-2024-22195, CVE-2024-34064** (xmlattr): trigger `jinja2.filters.do_xmlattr` is used from templates, never
  called from Python; a code search can never find it. Structural limit, not only a spec issue. *miss risk* for apps
  whose templates use `|xmlattr`.

### Pillow
- **Distribution name instead of import name** (`Pillow.Image.open`, `Pillow.PIL.Image.open`): CVE-2023-4863,
  PYSEC-2023-175, CVE-2026-59204, CVE-2024-28219. *miss risk* (fixed by name normalisation).
- **CVE-2023-4863**: also lists `Image.new` and `Image.save` (encoding does not decode WebP); arg_form on a `filename`
  extension, but the app passes a stream. *false alarm* risk.
- **CVE-2024-28219**: `Pillow.ImageCms.ImageCms` (no such API); condition "versions before 10.3.0" is not a code condition.
- **CVE-2026-42308** (font integer overflow): empty trigger list (should be `ImageFont.truetype` / FreeType fonts). *coverage*.
- **CVE-2026-42310** (PDF trailer loop): lists `PIL.Image.open` with `format=PDF`, but Pillow cannot read PDFs:
  `PdfImagePlugin` registers save only, and `PdfParser` runs only when saving with `append=True`. `parent_triggers`
  = Pillow → itself. **Caused a false alarm** (native-reachable).
- **CVE-2026-54058** (McIdas mmap): lists `Image.open`, `tobytes`, `getpixel`, `convert`; the condition "opened from a
  filename" is right, but no arg_form captures file name vs stream. **Caused a false alarm** (the app opens a stream).
- **CVE-2026-54059** (PCF font): lists `Image.frombytes` (too broad) and `_decompression_bomb_check` (the guard, not the flaw).
- **CVE-2026-54060** (FontFile.compile): lists `PIL.Image.new` (too broad). *false alarm* risk.
- **CVE-2026-55379** (BdfFontFile): lists `PIL.Image.new` and `PIL.Image.frombytes`: the flaw is Pillow's own
  `Image.new` call inside `BdfFontFile`, not the application's. **Caused a false alarm** (native-unreachable calls
  `Image.new("RGB", (120, 24), ...)` with a fixed size).
- **CVE-2026-59197, CVE-2026-59199**: `native_feature.library` = "libImaging" (Pillow's own C code, not a bundled
  library). *harmless*.
- **CVE-2026-59204** (JPEG2000): root `Pillow.`; arg_form on a `*.jp2` file name, the app passes a stream. *miss risk*.
- **CVE-2026-59198, 59200, 59205, 55380, 55798, 50447**: reasonable.

### cryptography
- **CVE-2023-50782** (RSA PKCS#1 v1.5 decryption timing in TLS servers): triggers `load_pem_private_key` /
  `load_pem_public_key`; the flaw is in RSA decryption with PKCS1v15 padding (`private_key.decrypt(...)`). Loading
  keys is not it. *false alarm / miss risk*.
- **CVE-2024-0727** (PKCS#12 NULL dereference): invented `pkcs12.PKCS12_load` (an OpenSSL C name); missing
  `pkcs12.load_key_and_certificates`, the most used API; nonsense `parent_triggers` (requests, urllib3). *miss risk*
  (caught only by the same-submodule rule, as needs review).
- **CVE-2024-26130**: module path `cryptography.pkcs12.serialize_key_and_certificates` (really
  `cryptography.hazmat.primitives.serialization.pkcs12...`). *harmless* with public-name matching.
- **CVE-2026-34073** (DNS name constraints): typo `cryptography.x5.09.Certificate.load_pem`; lists certificate
  *loading*, while the flaw is in chain verification (`cryptography.x509.verification`). *false alarm* risk.
- **CVE-2026-69249** (duplicate self-signed certs slow verification): wrong module
  `cryptography.hazmat.primitives.asymmetric.x509`; lists loading instead of verification. *false alarm* risk.
- **CVE-2026-69248, CVE-2026-26007, CVE-2023-49083**: reasonable.
- **GHSA-537c-gmf6-5ccf** (bundled OpenSSL, secadv 2026-06-09, 18 issues): `trigger_symbols` = `['cryptography']` and
  native wrappers = the whole package, so Fernet counts as reaching the flaws. None of the 18 issues involves AES-CBC
  or HMAC-SHA256; they are in PKCS7_verify, CMS, QUIC, OCSP, ASN.1 decoding, AES-OCB/SIV, PKCS#12 PBMAC1, CMP, DH
  and X.509 e-mail checks. **Caused a false alarm** (native-unreachable).
- **GHSA-h4gh-qq45-vh27, GHSA-v8gr-m533-ghj9**: wrappers are the internal `cryptography.hazmat.bindings.openssl`
  binding; no public API. *coverage*.

### tqdm
- **CVE-2024-34062**: internal `tqdm.cli.cast`; the public trigger is running tqdm's CLI (`python -m tqdm`,
  `tqdm.cli.main`) with untrusted arguments. *harmless* in the reachability repo (tqdm is used as a library).

## General patterns
1. qwen names the function **where the fix was made** (from the diff) rather than the **public API that reaches it**.
2. It rarely fills `parent_triggers`, and when it does they are sometimes nonsense.
3. `arg_forms` values are often descriptions (`'untrusted_template'`, `'contains spaces'`), which cannot match code.
4. For format- or feature-specific flaws it lists the generic entry point (`Image.open`, `Image.new`) without a
   usable condition, which leads to false alarms once the narrow question says "yes".
